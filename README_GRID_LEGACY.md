# KGridBot (기존 그리드 버전 보존)

이 문서는 이전 버전의 기록입니다. 기본 실행기는 Elliott BTC로 변경되었습니다. 이전 그리드는 `.venv/bin/python -m kgridbot --config configs/paper.example.json`으로만 실행하세요.

BTC 선물 롱 그리드를 로컬 PC에서 설정하고 모의 운용하는 한국어 프로그램입니다. **현재 검증된 실행 모드는 paper입니다.** 실제 주문 엔진은 자체 구현이며 Hummingbot 런타임을 실행하지 않습니다. 처음 요청했던 Hummingbot 기반 주 매매 엔진 요구사항은 아직 충족되지 않았습니다. `live` 시작은 코드에서 차단합니다.

## 실행

macOS에서는 **`Start KGridBot.command`를 더블클릭**하거나 프로젝트 디렉터리에서 실행합니다.

```bash
./start.sh
```

가상환경과 분석 패키지를 준비하고 브라우저를 엽니다. 최초 설치에만 인터넷이 필요하며 기본 모의거래·분석은 API 키, 유료 서비스, OpenAI API 없이 작동합니다. 분석 패키지 고정 목록은 Python 3.12 이상, 이 PC에서는 Python 3.13.3으로 검증했습니다. macOS Apple Silicon에서 직접 검증했고 Linux 실행은 별도 검증하지 않았습니다.

화면 주소: [http://127.0.0.1:8765](http://127.0.0.1:8765). 해당 포트가 사용 중이면 `./start.sh --port 8766`을 실행합니다.

분석 패키지 없이 최소 모의거래만 실행할 때는 Python 3.11 이상으로 아래 명령을 사용합니다. QuantStats 미설치 상태는 화면에 표시됩니다.

```bash
python3 -m kgridbot --config configs/paper.example.json
```

서버 시작 후 **매매 시작** 버튼을 눌러야 진입 주문이 생성됩니다. 브라우저 종료·새로고침은 Python 엔진을 중지시키지 않습니다. 프로그램 재시작 시에는 주문·체결 상태를 읽고 수동 시작을 기다립니다. 터미널 `Ctrl+C`는 진입 중단과 미체결 매수 취소 후 프로세스를 종료합니다. 보유 포지션은 자동 정리하지 않으므로 완전히 종료하려면 먼저 화면에서 포지션 정리를 실행합니다.

## 설정과 화면

- **운용 현황:** 가격·그리드 차트, 포지션·평균 진입가·레버리지·증거금, 실현·미실현 손익·수수료·펀딩, 위험 한도, 주문·체결·이벤트.
- **전략 설정:** 1~5배 정수 레버리지, 등간격·등비율, 가격 범위·그리드 수, 배정 자본·주문 명목가치, 동시 주문 수, 노출·손실 한도, 비용 가정. 주문 수량과 비용을 적용 전에 검증합니다.
- **시나리오 분석:** QuantStats 수익률·낙폭, 순자산 차트, 횡보·급락·상승 시나리오. 일별 수익률 30개 미만에서는 연율화 샤프·변동성을 표시하지 않습니다.

설정 변경은 모의거래에서 **진입 중단 + 포지션 0 + 미체결 주문 0**일 때 적용됩니다. 필요하면 포지션 정리를 먼저 실행합니다. 저장 후에도 자동 재개되지 않습니다. 자본 변경은 손익으로 계산하지 않도록 분석 수익률에서 보정합니다.

UI 설정은 SQLite에 저장되며 다음 실행에서 JSON보다 우선합니다. JSON은 새 DB의 초기 설정입니다. 기존 기록을 유지하면서 새 모의를 시작하려면 다음처럼 다른 DB를 지정합니다.

```bash
./start.sh --database data/experiment-02.sqlite3 --port 8766
```

BTCUSDT가 기본입니다. BTCUSDC는 별도 설정 파일과 별도 DB로 실행해야 하며 운용 중 통화를 자동 전환하지 않습니다. 전략은 롱·격리·One-way로 제한합니다. 숏, 헤지 모드, 5배 초과, 손실에 따른 자동 증액·범위 확대는 지원하지 않습니다.

## 주문과 위험 관리

매수 부분 체결마다 해당 체결 수량만 상위 그리드의 reduce-only 익절에 배정합니다. 각 주문을 제출하기 **직전**, 후보 주문까지 포함한 노출을 계산합니다. 배정 자본에 누적 순손익을 반영한 자산과 설정 한도 중 더 엄격한 한도를 적용하고 증거금 10%를 남깁니다. 주문 명목가치에 레버리지를 중복 곱하지 않습니다.

진입 중단은 미체결 매수만 취소하고 익절·보호 주문을 유지합니다. 범위 밖에서도 미체결 매수를 취소하고 기존 포지션은 익절·손절로 관리합니다. 손실 한도는 미실현 손익·수수료·펀딩을 포함하며 서울 날짜별 기준을 저장합니다. 정지 상태는 재시작이나 날짜 변경만으로 해제되지 않습니다.

포지션 정리·비상 정지는 진입·익절 주문을 취소하고 잔여 수량을 시장가 reduce-only로 청산합니다. 수량 0을 확인한 다음에만 보호 주문을 제거합니다. 보호 등록 실패 시 진입을 취소하고 포지션 정리를 시도하며 결과가 불명확하면 오류로 남깁니다. Post-only 익절이 현재 호가를 가로지르면 시장가로 바꾸지 않고 진입을 중단한 채 재검증합니다.

명령·틱 처리는 하나의 잠금으로 직렬화합니다. 중복 DB 실행은 OS 파일 잠금으로 차단합니다. 체결·포지션·수수료 변경은 하나의 SQLite 트랜잭션으로 저장하고 체결 ID, 주문 의도, 처리 여부를 보존합니다. HTTP 제어는 loopback, Host·Origin 검사, CSRF 토큰으로 제한합니다.

## 데이터와 분석 한계

기본 가격은 합성 파형이며 실제 BTC 시세가 아닙니다. 차트는 최근 300개 메모리 표본, DB는 분 단위 마지막 표본과 자본 변경 시점을 보존합니다. 운용 분석은 최근 200,000개 저장 표본 기준이며 분 내부의 낙폭은 놓칠 수 있습니다. 라이브 화면의 펀딩은 기본 합성 피드에서 0입니다. 스트레스 분석에서는 별도 합성 펀딩 정산 이벤트를 자산에 가감합니다.

시나리오는 현재 가격 구간에 비례해 생성하는 고정된 합성 검증 경로이며 역사적 백테스트가 아닙니다. 각 단계는 1시간이고 펀딩 시각·요율은 시나리오 가정입니다. 실제 거래소의 대기열·유동성·청산가격·봉 내부 체결 순서는 재현하지 않습니다. 파라미터 최적화를 하지 않았으므로 시장 데이터 기반 학습·검증 구간의 성과라고 해석할 수 없습니다.

## Testnet과 Live

`configs/testnet.example.json`은 테스트넷 전용 URL·환경변수·DB를 사용합니다. 키가 없으면 거래를 시작하지 않고 원인을 표시합니다. 키는 로컬 환경변수에만 두고 코드·JSON·브라우저로 전달하지 않습니다.

```bash
.venv/bin/python -m kgridbot --config configs/testnet.example.json
```

테스트넷은 One-way·ISOLATED·설정과 동일한 1~5배 레버리지, 서버 시간, 거래 권한·담보 잔고, 거래소 주문 규칙·수수료를 조회합니다. 계정 설정을 자동 변경하지 않습니다. 동일 키·심볼의 로컬 중복 프로세스를 차단하지만 다른 키나 다른 PC의 봇은 감지하지 못하므로 전용 계정·심볼을 사용해야 합니다.

Binance 연결 코드는 최신 `/fapi/v1/algoOrder` 보호 주문, 주문 ID 복구, 체결·펀딩 기록을 구현했으나 **실제 테스트넷 계정으로 주문·취소·손절을 검증하지 않았습니다.** live는 `live_trading_enabled=true`만으로도 열리지 않습니다. 계정·지역별 상품 이용 가능 여부, Hummingbot 런타임 통합, 장애 중 잔여 진입 주문 통제, 실제 청산·수수료·체결 조건이 남아 있습니다. 실계좌 주문과 입출금은 실행하지 않았습니다.

## 검증과 기록

```bash
.venv/bin/python -m unittest discover -s tests -v
.venv/bin/python -m kgridbot.backtest --config configs/paper.example.json --output artifacts/backtest.json
```

GUI 검증은 `scripts/verify_ui.py`가 disposable paper 서버에 설정·주문 명령을 보내므로 별도 DB에서 실행합니다. Playwright는 테스트 전용 의존성입니다.

```bash
.venv/bin/python -m pip install playwright==1.55.0
.venv/bin/python -m playwright install chromium
.venv/bin/python -m kgridbot --database artifacts/ui-test.sqlite3 --port 8765
# 별도 터미널
.venv/bin/python scripts/verify_ui.py
```

백업은 프로그램을 종료한 뒤 사용한 `.sqlite3` 파일과 설정 파일을 함께 보관하면 됩니다. DB 안에 UI 설정, 정지 상태, 체결, 이벤트, 분 단위 자산 기록이 포함됩니다. API 키는 별도 비밀 저장소에서 관리합니다.
