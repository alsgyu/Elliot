# Elliott BTC 실행 검증

최신 선택형 다중 후보 및 위험 통제 검증은 [v2 검증 결과](ELLIOTT_V2_VERIFICATION.md)를 참고하세요. 아래는 이전 단계의 기록입니다.

검증일: 2026-10-02 / macOS arm64 / Python 3.13.3 / `ew-causal-1.0`

## 요약

- 전체 단위·회귀·HTTP 테스트 **114개 통과**. 기존 그리드 테스트도 포함합니다.
- 실제 Binance USD-M 공개 API의 마감봉·호가·마크 가격·펀딩·주문 필터 수신 성공.
- Playwright: 1440px, 390px, 360px에서 5개 화면 확인. 페이지 가로 넘침·버튼 글자 넘침·JS 오류 없음.
- wheel 빌드 성공. 별도 가상환경 설치 후 로컬 HTTP 화면·JS·CSS·아이콘·규칙 MD 제공 확인.
- 깨끗한 Python 환경의 기본 CA 연결 실패를 재현했고 `certifi==2026.7.22` 의존성 및 첫 실행 설치로 해결. HTTPS 인증서 검증을 끄지 않았습니다.
- 최종 앱을 실제 공개 시세의 PAPER 모드, 신규 진입 중단, 키 미등록 상태로 확인했습니다.
- **실거래 주문·입출금 0건. 사용자 계정의 데모/실거래 서명 API와 실제 체결은 미검증입니다.**

## 자동 테스트 범위

확정 피벗의 과거 소급 변경 방지, 마감 전 봉 제외, 미래 자료를 붙여도 과거 결정 불변, 데이터 누락·비정상 값 차단, 상승·하락 파동 규칙 대칭, 실제 5-3 스윙 증거, 하위 이력 부족 시 주문 금지, 주봉 거부권과 동급 충돌 관망을 검사했습니다.

실행 계층은 비용 후 위험 수량, 레버리지 1~5배, 거래소 시장가 수량 제한, 진입 전후 손절 활성 확인, 중복 client ID 처리, 응답 유실 시 재전송 금지, 결과 불명 청산 의도 보존, 포지션 전체 체결량 정산, 실제 수수료·펀딩의 이중 차감 방지, 재시작·모드 분리·키 소유권·프로세스 잠금을 검사했습니다. 거래소 주문 검사는 모의 응답입니다.

모의 진입·청산 시 MD 근거 자동 생성과 SQLite 기록도 검사했습니다. 매매 신호를 주입한 실행 경로 시험은 시장에서 그 신호가 발생했다는 뜻이 아닙니다.

HTTP 검사는 CSRF, Origin/Host, 정적 파일 경로, 합성 환경의 실거래 전환 차단, 제어 명령의 검증을 포함합니다. 보안 감사 전체를 대신하지는 않습니다.

## 화면과 재현

스크린샷: `artifacts/elliott-ui/`. 합성 환경 15개 화면과 최종 실제 시세 PAPER 화면을 저장했습니다. 차트의 비어 있지 않은 캔버스 픽셀, 네 시간봉 전환, 설정 저장·새로고침 유지, 시작·중단, 정리 확인/취소, 기록, 키 입력 차단, 재생 완료, 규칙 MD 다운로드를 검사했습니다.

```bash
.venv/bin/python -m unittest discover -s tests
.venv/bin/python scripts/verify_elliott_market.py
```

화면 자동 검증은 **일회용 합성 저장소**에서만 실행합니다. 첫 터미널:

```bash
./start.sh --sample --port 8766 --data artifacts/elliott-ui-test
```

두 번째 터미널:

```bash
.venv/bin/python scripts/verify_elliott_ui.py
```

Playwright는 개발 검증용이며 사용자의 기본 실행 의존성이 아닙니다. 실운용 저장소로 화면 자동 시험을 실행하지 않습니다.

## 남는 한계

엘리엇 해석은 유일하지 않습니다. 적합도는 경험적으로 보정된 확률이 아닙니다. 자동 진입은 하위 스윙을 확인한 보수적 3파·5파에 한정하며 복합조정·대각선·절단 등의 완전 판독은 지원하지 않습니다. OHLC 재생은 실제 호가·부분체결·마크 가격·강제청산을 완전히 재현하지 않습니다.

거래소 키 권한·지역별 계정 자격·실제 계정 주문 수락 여부는 프로그램의 계정 검사와 사용자 데모 운용에서 확인해야 합니다. 보호 주문이 거부되거나 상태가 불명확하면 신규 진입을 차단합니다. 네트워크 단절·거래소 장애·갭으로 실제 손실은 설정한 위험 예산을 초과할 수 있습니다.

## 2026-10-03 연결 검사 수정

사용자 연결 과정에서 `canTrade` 오판정을 발견했습니다. V3 잔액 응답에 없는 필드를 읽어 거래 가능한 계정도 미통과로 표시하던 오류를 `/fapi/v1/accountConfig` 조회로 수정했습니다. 공식 계정 API 명세와 등록된 계정의 읽기 전용 조회로 확인했습니다. 최초 114개 테스트에는 이 응답 형식에 대한 검증이 빠져 있었습니다.

V3 응답에 `canTrade`가 없는 정상 사례, 계정 설정에서 실제 false인 사례, 필드 누락, 문자열 true, 나머지 설정 불일치에 대한 5개 회귀 테스트를 추가했습니다. 오류를 무시하거나 미확인 값을 통과시키지 않습니다. UI에는 실제 담보·증거금 모드를 표시하고, 고정된 권한 안내가 실측 결과처럼 보이지 않도록 요구 설정으로 구분했습니다. 거래소 설정·자금 이체·실주문은 변경하지 않았습니다.

수정 후 전체 **119개 테스트 통과**. 실행 중인 서버에서도 올바른 계정 거래 권한이 통과하고 실제 담보·증거금·레버리지 불일치는 계속 차단됨을 확인했습니다. Playwright로 1440/390/360px 연결 화면, 새 권한 안내, 자동매매 중단 상태, JS 오류 없음을 재확인했습니다.

### 주문 권한 검사 실패 시 이전 결과 표시 수정

후속 점검에서 `/order/test`가 401을 반환할 때 검사 전체가 예외로 끝나 이전 증거금 결과가 화면에 남는 문제를 확인했습니다. 이제 현재 계정 설정 결과를 유지하면서 **주문 권한 검사 미통과**로 표시합니다. 계정 조회 자체가 실패하면 과거 결과를 폐기하고 최신 검사 중단으로 표시합니다. 시세 없이 주문 권한 검사 완료로 표시하지 않으며, 실패 시 자동 재시도나 매매 활성화도 하지 않습니다.

401·타임아웃·시세 미수신·오래된 결과 폐기·실거래 시작 차단을 검사하는 회귀 테스트 5개를 추가했습니다. 전체 **124개 테스트 통과**. 실제 주문, 거래소 설정 변경, 입출금은 수행하지 않았습니다.
